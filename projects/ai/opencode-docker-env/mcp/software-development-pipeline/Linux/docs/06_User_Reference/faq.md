# FAQ

**Class**: 5 (Ops/User) | **Persona**: All

## General

### What is this project?
A Linux-native, CMMI Level 4 (Quantitatively Managed) software development
pipeline. OpenCode is the single entry point (R5) and enforces the workflow
order Requirements → Coding → DevSecOps → Documentation (W1), with mandatory
security gates (R7-R10) and quantitative process control (C4-1..5).

### Why "Level 4"?
CMMI Level 4 means the process is *measured and controlled*: every build records
defect density, and 3-sigma statistical process control (C4-3) decides whether a
merge is statistically safe. Level 4 adds the SPC and prediction machinery that
lower levels do not have.

### Is it free and local-first (R6)?
Yes. The toolchain is Node.js (LTS), OpenCode, and open-source tools (ESLint,
npm audit, Jest, SQLite). A local Ollama provider is registered as an optional
fallback, so no cloud vendor is required.

## Running the pipeline

### How do I run the full pipeline?
```bash
npm run pipeline            # project directory
/pipeline                   # any directory, after npm run deploy (R14)
```

### What is the difference between the run variants?

| Variant | Skips | Use when |
| :--- | :--- | :--- |
| `pipeline` | nothing | every real delivery |
| `pipeline:skipdocs` | Phase 4 (docs) | you only need specs + code + gates |
| `pipeline:skipsecurity` | Phase 3 (gates) | local experimentation only — never for merge |

### Why did my run stop with exit 1?
Any phase or gate that fails BLOCKS the build (R10). Read the `[FAIL]` line,
then consult the [Troubleshooting-Guide](Troubleshooting-Guide.md).

## Security gates

### What are R7, R8, R9, R10?

| Gate | What it does |
| :--- | :--- |
| R7 | Runtime protection — no `.env`, `.gitignore` excludes secrets, no hardcoded secrets in `src/`, `scripts/`, `tools/` |
| R8 | SAST — ESLint with `--max-warnings 0` over all `.js` |
| R9 | SCA — `npm audit --audit-level=high` |
| R10 | Mandatory gate — any failure exits non-zero and blocks the merge |

### Can I skip the security gates?
`pipeline:skipsecurity` exists for local testing, but the acceptance rules treat
a bypassed gate as a block on merge (R10). Do not ship work that skipped Phase 3.

## Quantitative management

### What is defect density (C4-1)?
`defect_density = (critical_vulns + high_vulns) / (loc / 1000)`. The target is
≤ 0.5 (Critical+High per thousand lines of change).

### What are UCL and LCL (C4-3)?
Upper/Lower Control Limits: `UCL = mean + 3σ`, `LCL = max(0, mean - 3σ)`. A
current defect density above the UCL signals an out-of-control process and
blocks the build.

### Why does `spc-control.js` print a baseline notice?
Control limits need at least 5 builds; prediction needs at least 10 builds.
Keep running the pipeline — the reports become statistically meaningful as
history accumulates.

### What happens when readiness is predicted above the goal (C4-5)?
`predict-readiness.js` auto-generates a remediation plan and runs it through
`opencode run` so the pipeline returns to control proactively, rather than
waiting for the next failure.

## Global deployment (R14)

### What is the global directory and why does it exist?
`~/.config/opencode/` is the single source of truth for the pipeline
executables, skills, tools, and the organizational metrics database. Syncing
there (R14) lets `/pipeline` run from any directory with zero dependency on
this repository.

### How do I deploy and when?
`npm run deploy` — after EVERY change to a resource listed in the deployment
table (skills, scripts, tools, rules, docs templates, AGENTS.md). Then restart
opencode so the new config loads. See the
[Administration-Guide](Administration-Guide.md).

### Why does my opencode crash at startup (C4-6)?
A `tools/*.js` file that runs top-level code on import (prints usage, calls
`process.exit`) crashes opencode because opencode auto-imports every `.js` in
`~/.config/opencode/tools/` in-process. Every tool must guard its CLI entry
with `require.main === module` or export a `tool()` definition. `npm run
deploy` refuses to deploy an unsafe tool.

## Documentation

### Which documents exist and who reads them?
Phase 4 produces 5 core docs, 15 audience docs, a toctree, and updates README.md.
See the [Table of Contents](../toctree.md) for the index and the audience of each doc.

### Where do LICENSE/CONTRIBUTING.md/SECURITY.md come from?
They are scripted by the pipeline from `scripts/templates/` (create-if-missing).
They are NOT generated by the doc-generation skill, which never overwrites them.
