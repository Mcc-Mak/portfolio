# SoD Matrix — md2csv-cli dogfood run

Generated by the Team Architect during Phase 0. The Orchestrator enforces these rules
ruthlessly: out-of-scope actions are rejected, logged to `logs/sod-violations.log`
(`ISO timestamp | role-id | attempted action | resolution`), and re-routed.

| Role | Tower | Allowed actions | Forbidden actions |
|---|---|---|---|
| pm-001 Product Manager | Product & Strategy | Define scope, user stories, use cases, acceptance criteria; facilitate Requirements & Business + Error/Validation TUI modules; prioritise requirements | Write production code, modify infrastructure, approve security scans |
| eng-001 CLI Engineer | Core Engineering | Implement parser/CLI in `src/`, write unit tests with QA, review architecture compliance, fix bugs, consume TUI transcripts | Approve security scans, modify compliance policies, declare gates passed |
| qa-001 QA & Automation Engineer | QA & Testing | Write test plan/cases/metrics; automate tests from Error/Validation answers; report quality status | Modify application code, change security controls, deploy/publish anything |
| ops-001 DevOps Engineer | DevOps & SRE | Packaging/bin config, install/uninstall flow, pnpm scripts, release checklist, operational docs | Write business logic in `src/`, define security policies, modify parsers |
| sec-001 Security & Compliance Officer | Security & Compliance | Own Security + GDPR/SOC2 TUI modules; run tools/adapters; enforce G4/G5; write security/compliance docs; inspect logs | Modify database schemas (none exist), write application code, approve their own findings |
| doc-001 Lead Technical Writer | Docs & Knowledge | Write/sync all reference docs, glossary, FAQ, user guide, README; transform transcripts into docs | Modify source code, modify infrastructure configuration |

Universal rules (apply to every role):

1. No role may mark a gate as passed except the Orchestrator after verifying evidence.
2. No role may edit generated files under `skills/`.
3. Every artifact records its producing role ID.
4. Cross-domain fixes are re-routed: e.g., a doc bug found by QA is logged and handed to doc-001, never patched by qa-001.
