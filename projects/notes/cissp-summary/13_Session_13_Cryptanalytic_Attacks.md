## Video V97: Vulnerabilities in Cryptographic Systems

**Objective:** To explain the inherent weaknesses in cryptographic systems.

### I. Categories of Cryptographic Vulnerabilities

| Category | Description |
| :--- | :--- |
| **Algorithm Weaknesses** | Using proprietary/unvetted algorithms; algorithms weaken over time (Moore's Law) |
| **Protocol Weaknesses** | Strong algorithm + weak protocol (e.g., SSH/HTTPS relying on vulnerable OpenSSL) |
| **Implementation Weaknesses** | Cryptographic protections naturally degrade; revisit lifecycle |
| **Key Management Weaknesses** | Weak keys (short, not random); key reuse; improper destruction; classification misalignment |

### II. Key Management Risks
- Keys must be **long** and **random** to be unpredictable
- Keys must **never be reused** and should be rotated periodically
- Keys past their "crypto period" must be destroyed to prevent replay attacks
- Protect keys at the **same classification level** as the data they secure

### III. The Cryptographic Lifecycle Vulnerabilities
- Plaintext → Cipher → Algorithm → Key → Ciphertext
- Vulnerabilities exist at **every step**

## Video V98: Cryptanalytic Attacks Part I (Known Plaintext, Brute Force)

**Objective:** To explain known plaintext attacks and their variants.

### I. Goal of Cryptanalytic Attacks
- **Objective:** Compromise a cryptographic system and discover the encryption key.

### II. Attack Vectors
- Plaintext, Ciphertext, Key (primary target), Algorithm/Cipher (fallback)

### III. Known Plaintext Attacks

| Attack Type | Description |
| :--- | :--- |
| **Brute Force Attack** | Trying every possible combination; eventually successful with enough time/resources |
| **Linear Cryptanalysis** | Uses linear math equations to perform statistical analysis of the cipher |
| **Meet-in-the-Middle Attack** | Targets ciphers with multiple rounds; encrypting/decrypting with every possible key to find a match |

### IV. Chosen Plaintext Attacks
- Selecting a specific portion of plaintext to encrypt and analyze (reduces analysis time)

### V. Differential Cryptanalysis
- Analyzing differences in ciphertext outputs based on changes in the input (bits of key or plaintext)
- **Best used with Chosen Plaintext** (small portions) to manage complexity

## Video V99: Cryptanalytic Attacks Part II (Ciphertext-Only, Hash Attacks)

**Objective:** To explain ciphertext-only attacks and hash-based attacks.

### I. Ciphertext-Only Attacks
- **Context:** Only ciphertext is available (key, plaintext, cipher are unknown)
- **Most common scenario** (e.g., sniffing network traffic)
- **Difficult and lengthy** to execute

### II. Ciphertext-Only Attack Techniques

| Technique | Description |
| :--- | :--- |
| **Related-Key Attack** | Compare same ciphertext generated by mathematically related keys |
| **Chosen Ciphertext Attack** | Focus on a specific portion of ciphertext; analyze decryption process |
| **Frequency Analysis** | Analyze character/group frequency to identify the cipher algorithm |

### III. Hash-Based Attacks

| Attack | Target | Description |
| :--- | :--- | :--- |
| **Pass-the-Hash** | Windows (LANMAN, NTLM) | Use stolen hash for authentication (no plaintext password needed) |
| **Kerberoasting** | Windows Kerberos | Harvest Kerberos password hashes to crack; targets Golden/Silver Tickets |
| **Birthday Attack** | Hash collisions | Based on Birthday Paradox; exploit collision likelihood |
| **Rainbow Table Attack** | Precomputed hash database | Compare stolen hashes against precomputed table of common passwords |

## Video V100: Cryptanalytic Attacks Part III (Implementation Attacks)

**Objective:** To explain implementation attacks, side-channel attacks, and user-focused attacks.

### I. Attacking the Cryptosystem (Algorithm & Implementation)

| Attack Type | Description |
| :--- | :--- |
| **Fault Injection** | Inject errors/invalid data; observe how the system responds |
| **Replay Attack** | Intercept and reuse encrypted messages (often authentication tokens); defenses: timestamps, expiration |
| **Side-Channel Attacks** | Analyze metadata from cryptographic process (timing, power consumption) |
| **Timing Attack** | Measure latency to deduce algorithm type or key material |

### II. Attacking the User

| Attack Type | Description |
| :--- | :--- |
| **Man-in-the-Middle (MITM)** | Intercept communications between two endpoints; capture credentials, ciphertext |
| **Ransomware** | Attacker encrypts user's data and demands payment for the key |
| **Social Engineering** | Trick authorized users into revealing cryptographic keys |

### III. Work Factor
- The amount of time, effort, and resources required to break a crypto system.
- **Golden Rule:** Never spend more on a safeguard than the value of the asset.

## Session Summary
Session 13 covers the **complete cryptanalytic attacks landscape** for the CISSP exam. Key takeaways include:

1.  **Cryptographic Vulnerabilities:** Algorithm, protocol, implementation, and key management weaknesses.

2.  **Known Plaintext Attacks:** Brute force, linear cryptanalysis, meet-in-the-middle.

3.  **Chosen Plaintext & Differential Cryptanalysis:** Focus on small portions to reduce complexity.

4.  **Ciphertext-Only Attacks:** Related-key, chosen ciphertext, frequency analysis (difficult and lengthy).

5.  **Hash-Based Attacks:** Pass-the-Hash, Kerberoasting, Birthday Attack, Rainbow Table.

6.  **Implementation Attacks:** Fault injection, replay attacks, side-channel, timing attacks.

7.  **User-Focused Attacks:** MITM, ransomware, social engineering.

8.  **Work Factor:** Compare cost to defeat a control vs. value of the asset.
